# Notion Second Brain — the contract

The second brain lives in **Notion**. There is no local vault any more: no qmd, no grep over
markdown, no Obsidian wikilinks, no Obsidian plugins, no git-committed notes. This skill is the
single source of truth for talking to it — the nine data sources, the property vocabulary, how to
write and link, the markdown dialect, the rate limit, and where the token lives. Every other
second-brain skill defers to this file; do not re-invent a Notion idiom.

Full endpoint/property/mention/escaping cheat sheet: `references/api-quickref.md`.

## 1. Environment

```bash
export WORKSPACE="${WORKSPACE:-$HOME/Documents/01-Projects/Notion-Migration}"

# Token: in the workspace .env, or exported. ~/.hermes no longer exists - do not look there.
if [ -f "$WORKSPACE/.env" ]; then set -a; . "$WORKSPACE/.env"; set +a; fi
export NOTION_API_VERSION=2026-03-11
export NOTION_API_TOKEN="${NOTION_API_KEY:?NOTION_API_KEY is not set - see this section}"

nb() {  # nb METHOD PATH [json-body]
  curl -sS -X "$1" "https://api.notion.com$2" \
    -H "Authorization: Bearer $NOTION_API_TOKEN" \
    -H "Notion-Version: $NOTION_API_VERSION" \
    -H "Content-Type: application/json" \
    ${3:+-d "$3"}
}
```

- **Token location:** `$WORKSPACE/.env` as `NOTION_API_KEY=ntn_...`, or an exported environment
  variable. Never inline it into a command, a page body, a report, or a commit.
- **Ledger cache:** `$WORKSPACE/migration/ledger/notion_db_ids.json` maps data-source name to
  data-source id. Read it first; refresh from the API when a name is missing or a call 404s.
- **Rate limit:** 3 requests/second per connection. Space calls ~350 ms apart; on `429` back off
  exponentially and honour the `Retry-After` header.
- **Never delete a Notion page.** Archive it (Status = Archived, or move it to the Archive data source)
  and log it. Duplicates are the one exception the user allowed to be removed — after a duplicate check.

## 2. The nine data sources

Databases are created as **data sources**: a database's parent is
`{ "type": "database_id", "database_id": "<id>" }`, and a page's parent is
`{ "type": "data_source_id", "data_source_id": "<id>" }`. The ids below are data-source ids.

| Data source | Main properties |
|---|---|
| **Inbox** | Name (title), Status (select: Dropped, Filed, Processing, Untriaged), Kind (select: Note, Clipping, Voice, Screenshot, Idea, Task), Suggested Area (relation → Areas), Source URL (url), Raw (rich text), Captured (date, created), Confidential (checkbox) |
| **Projects** | Name, Status (select: Active, Archived, Blocked, Done, Idea, Paused), Area (relation → Areas), Priority (select: P0–P3), Health (select: On track, At risk, Off track), Start (date), Target (date), Tasks (relation → Tasks), Notes (relation → Notes), Tags (multi-select), Confidential, Created (date, created), Updated (date, last edited) |
| **Tasks** | Name, Status (select: Todo, In progress, Blocked, Done, Cancelled), Done (formula), Due (date), Priority (select: P0–P3), Project (relation), Area (relation), Context (select: Computer, Home, Errands, Calls, Anywhere), Source (relation → Notes/Daily Notes), Confidential |
| **Notes** | Name, Type (select: Guide, Note, Overview, Readme, Reference, Ticker), Tags (multi-select), Aliases (multi-select), Date (date), Status (select: Active, Archived, Completed, Evergreen, Investigation, Resolved, Seed, Seedling, Stale), Area, Project, Related (relation → Notes), Sources (relation → Notes), Ticker (select), Verified (date), Stale After (date), Generated By (text), Generated At (date), Source URL (url), Confidential |
| **Areas** | Name, Status (select: Active, Archived, Dormant, Ongoing), Focus (select), Projects / Tasks / Notes (relations), Tags, Confidential |
| **Decisions** | Name, Date, Status (select: Accepted, Overturned, Proposed, Rejected, Superseded), Area, Project, Supersedes (relation → Decisions), Rationale (rich text), Source (relation → Notes), Confidential |
| **Daily Notes** | Name (`YYYY-MM-DD`), Date, Week (text), Status (select: Active, Archived), Tags, Related (relation → Notes), Confidential |
| **Archive** | Name, Type (select: Daily Note, Note, Overview, Readme, Reference), Status (select: Active, Archived, Completed, Seed, Stale), Original Path (text), Archived (date), Tags, Related (relation → Notes), Confidential |
| **Templates** | plain pages under the "Templates" parent page (13 of them: Atomic Note, Daily Note, Decision, Learning Note, Meeting, Project Note, Project, Reference, and the rest of the vault set) |

Title emoji by type: 📝 Note · 📚 Reference · 🧭 Overview · 📘 Readme · 🧪 Guide · 📈 Ticker.

## 3. Looking up ids

```bash
# 1. ledger (fast path)
cat "$WORKSPACE/migration/ledger/notion_db_ids.json"

# 2. fall back to the API - data sources are searchable objects
nb POST /v1/search '{"query":"Notes","filter":{"property":"object","value":"data_source"}}'
#    -> results[].id where results[].object == "data_source"

# 3. refresh the ledger after a change (keep it in sync, never hand-edit ids)
python3 -c "import json,os;ws=os.environ.get('WORKSPACE',os.path.expanduser('~/Documents/01-Projects/Notion-Migration'));p=os.path.join(ws,'migration/ledger/notion_db_ids.json');os.makedirs(os.path.dirname(p),exist_ok=True);json.dump(json.load(open(p)),open(p,'w'),indent=2)"
```

Ledger shape: `{"Inbox": "<data_source_id>", "Projects": "<id>", …, "root_page_id": "3f04c3376067800f8d03c40b25d6fa0c"}`.
The root page id (`3f04c3376067800f8d03c40b25d6fa0c` = "Second Brain") is the parent of the data
sources and of the Templates page.

## 4. Querying and searching

```bash
# Query a data source (filter + sorts use the data-source query shape)
nb POST "/v1/data_sources/$NOTES_DS/query" '{
  "filter": {"property":"Type","select":{"equals":"Reference"}},
  "sorts": [{"property":"Date","direction":"descending"}],
  "page_size": 20
}'

# Composite filter: property AND relation
nb POST "/v1/data_sources/$NOTES_DS/query" '{
  "filter": {"and":[
    {"property":"Status","select":{"equals":"Active"}},
    {"property":"Confidential","checkbox":{"equals":false}},
    {"property":"Date","date":{"on_or_after":"2026-10-01"}}
  ]}
}'

# Search pages by title (search covers titles and properties, not arbitrary body text)
nb POST /v1/search '{"query":"return to bali","filter":{"value":"page"},"page_size":20}'
```

Always **search before you create** — the idempotency rule. Follow `next_cursor` until null.

## 5. Writing

One request per note. Page content is **enhanced markdown** (`markdown_version` `v1`, the default)
sent as the `markdown` body param — not hundreds of block calls.

```bash
nb POST /v1/pages '{
  "parent": {"type":"data_source_id","data_source_id":"$NOTES_DS"},
  "properties": {
    "Name": {"title":[{"text":{"content":"Title here"}}]},
    "Type": {"select":{"name":"Reference"}},
    "Status": {"select":{"name":"Active"}},
    "Date": {"date":{"start":"2026-10-21"}},
    "Tags": {"multi_select":[{"name":"type/reference"}]},
    "Source URL": {"url":"https://example.com/article"},
    "Related": {"relation":[{"id":"$OTHER_PAGE_ID"}]},
    "Confidential": {"checkbox":false}
  },
  "markdown": "# Title here\n\nBody written as enhanced markdown."
}'
```

- **Update properties:** `PATCH /v1/pages/{page_id}` with `{"properties": {…}}`.
- **Update the body:** `PATCH /v1/pages/{page_id}/markdown` with either
  `{"type":"replace_content","replace_content":{"new_str":"…"}}` (whole body) or
  `{"type":"update_content","update_content":{"content_updates":[{"old_str":"…","new_str":"…"}]}}`
  (targeted find/replace).
- **Read the body back:** `GET /v1/pages/{page_id}/markdown` → `{"markdown": "…", "truncated": false}`.
- **Move a page**: no move endpoint — create the new page, then delete or archive the old one.
- **Tasks** are a data source, not checkboxes inside a note. A task row carries Name, Status, Due,
  Priority, Project/Area relations, and optionally a `Source` relation back to the note it came from.

## 6. Linking notes

Two mechanisms, used together:

1. **Relation property** (the link graph): `Related`/`Sources` on Notes, `Project`/`Area` on
   Notes and Tasks, `Supersedes` on Decisions, `Source` on Tasks and Decisions. Relations are
   **bidirectional in Notion** — set one side only, never hand-write the backlink.
2. **Inline mention** (human-readable, inside a body):

`<mention-page url="https://www.notion.so/$PAGE_ID">Page title</mention-page>`

There is no `notion://` URI scheme. A mention needs the *page* id, not the data-source id.

## 7. Frontmatter → properties

The vault's YAML frontmatter is gone; it becomes properties plus a **Metadata** section.
Nothing may be dropped.

| Frontmatter key | Destination |
|---|---|
| title | Name (title) |
| type | Type (select: Guide, Note, Overview, Readme, Reference, Ticker) |
| date | Date |
| created / updated | auto on Projects; elsewhere keep them in Metadata |
| status | Status (see the mapping below) |
| tags | Tags (multi-select) — drop `status/*` tags that duplicate the Status property |
| aliases | Metadata section |
| source | Sources (relation) when it points at a note; Source URL (url) when it is a link |
| links | Related (relation) |
| verified | Verified (date) |
| stale_after | Stale After (date) |
| generated.by / generated.at | Generated By (text) / Generated At (date) |
| ticker | Ticker (select) |
| domain, author, published, period, sessions, location, description, keywords, doi, … | Metadata section |

**Status mapping.** The Notion select options are Title Case and narrower than the vault vocabulary:

| Vault status | Notion Status | Otherwise |
|---|---|---|
| active | Active | — |
| archived | Archived | — |
| completed, done | Done (Tasks) | keep `status/done` as a tag on Notes |
| note | (no option) | keep `status/note` as a tag and echo it in the Metadata line |
| seed | Seed | — |
| seedling | Seedling | — |
| evergreen | Evergreen | — |
| investigation | Investigation | — |
| resolved | Resolved | — |
| processed | Active | — |
| done, completed | Completed (Notes, Archive) / Done (Tasks) | — |
| stale | Stale (Notes, Archive) | — |

`type: area` → **Areas**; `type: Daily Note` → **Daily Notes**; every other type → **Notes**.

## 8. Markdown dialect

| Construct | How to write it |
|---|---|
| Headings | `#` to `####` |
| To-do | `- [ ]` / `- [x]` |
| Table | GFM pipe table (blank line before and after) |
| Callout | `<callout icon="emoji" color="blue_bg">` … children indented with a TAB … `</callout>` |
| Code | fenced; use **four** backticks as the outer fence when the content contains three-backtick runs |
| Block colour | `{color="Red"}` on the first line of a block |
| Inline colour | `<span color="Red">text</span>` |

**Escaping.** Outside code blocks prefix each of these with a backslash —
\` ` * ~ $ [ ] < > { } | ^. Inside code blocks escape nothing.
A literal pipe inside a table cell is written \\|.

## 9. Views (dashboards)

Views are creatable by API: `POST /v1/views` with
`{data_source_id, name, type, configuration, filter, sorts}`. `type` is one of
`table | board | list | calendar | timeline | gallery | form | chart | map | dashboard`.
`filter` and `sorts` use the data-source query shape. Grouping lives in
`configuration.group_by`. Example:

```bash
nb POST /v1/views '{
  "data_source_id": "$TASKS_DS",
  "name": "Now - next 7 days",
  "type": "table",
  "configuration": {"type":"table","group_by":{"type":"date","property":"Due"}},
  "filter": {"and":[
    {"property":"Status","select":{"does_not_equal":"Done"}},
    {"property":"Due","date":{"on_or_after":"2026-10-21","on_or_before":"2026-10-28"}}
  ]},
  "sorts": [{"property":"Due","direction":"ascending"}]
}'
```

Useful defaults: Inbox = table, filter `Status = Untriaged`, sort Captured desc · Projects = board grouped by Status · Now = Tasks in the next 7 days · All Tasks = Tasks grouped by Area · Orphans = Notes with empty `Related` · Stale = Notes with `Stale After` < today.

## 10. Limits and failure modes

- 3 requests/second; space calls, back off on 429.
- A single markdown payload must stay under 5000 blocks. Pages larger than ~20,000 blocks come back
  **truncated** — check the `truncated` flag on read-back and split the write.
- File URLs returned by Notion are **pre-signed and expire**. Re-upload an asset instead of
  re-linking an old URL. Durable binaries belong in Google Drive.
- A rich-text value over 2,000 characters is rejected — split long paragraphs.
- An unknown select value creates a new option — check section 2 before writing, never invent option names.

## 11. Rules

- Search before create; update instead of duplicating.
- Set relations on one side only; add an inline mention when a human needs to see the link.
- Confidential rows: set the checkbox, and skip reading them on a non-whitelisted model.
- Never write a local vault file, a `[[wikilink]]`, or a git commit for second-brain content.
- Rate-limit yourself even in batch loops: 350 ms between calls.
